# Self-review checklist

Run this before every draft goes to your supervisor. Be honest; every item you catch is one your supervisor does not have to.

## The three questions
- [ ] A reader can find *why*, *what* and *how* within the first two pages.
- [ ] The Heilmeier questions (docs/01) each have a two-sentence answer somewhere in the document.

## Problem and questions
- [ ] The problem statement is one paragraph and stands alone.
- [ ] It names a quantity, a failure mode or a missing study, not just a field.
- [ ] There is one aim and three to five objectives.
- [ ] Every objective has a metric and a tolerance, and is not merely an activity.
- [ ] Every objective traces to a sentence in the literature review and a paragraph in the methodology.
- [ ] Delimitations are stated and separated from limitations.
- [ ] The title matches the problem statement.

## Literature
- [ ] Organised by theme or method, not by author or date.
- [ ] Each subsection ends by stating what remains unclear.
- [ ] A comparison table of prior work makes the gap visible.
- [ ] Every cited source has been read. Every AI-suggested reference has been verified against the actual PDF.
- [ ] Seminal works and the five to ten closest papers are present.

## Methodology
- [ ] Each major method choice is justified against an alternative.
- [ ] Code verification, solution verification and validation are each addressed, by name.
- [ ] The validation dataset is named, with the quantities compared and the tolerance.
- [ ] Uncertainty quantification approach is stated.
- [ ] A test matrix with estimated computational cost is included.
- [ ] Hardware, software versions and storage are stated.
- [ ] Preliminary results, if any, are included and labelled.

## Feasibility
- [ ] Gantt chart has one section per objective, writing bars from early on, and 15 to 20% contingency.
- [ ] Milestones are deliverables.
- [ ] Resources table shows what is secured and what is pending.
- [ ] Risk register has three to six entries with mitigations you control.
- [ ] A feasibility paragraph closes the section.

## Ethics, data and AI
- [ ] Ethics clearance route confirmed, not assumed.
- [ ] Data management plan: what, where, naming, access, retention.
- [ ] AI tool use disclosed; no Tier 1 content was AI-drafted.
- [ ] Turnitin implications of reused material considered.

## Writing
- [ ] UK English; no em dashes.
- [ ] SI units with spaces; symbols defined at first use; nomenclature list present.
- [ ] Every figure and table is referred to in the text, has a self-contained caption, and is legible at final size.
- [ ] Equations dimensionally consistent.
- [ ] Abstract written last; five sentences; no undefined acronyms.
- [ ] Department's template, page limit and reference style followed.
- [ ] Spell-check and a read-aloud pass completed.

## Repository
- [ ] Proposal is under version control.
- [ ] This draft is tagged with a version number.
